# PM Emotes — EmotePreviewer manifest consumer

`client/NUI/js/preview-library.js` validates EmotePreviewer's experimental version-1 manifest and immutable media paths. `main.js` initializes `preview-panel.js` at NUI startup. The panel loads only the selected/highlighted preview and retains its placeholder for missing, ambiguous or failed media. Stale image callbacks are ignored and image requests are cleared as the menu selection and lifecycle change.

The consumer indexes the producer's full identity (`source`, `category`, `command`). Because the live menu does not expose the producer's source/category tuple, `preview-identity.js` resolves only commands that match exactly one producer entry; ambiguous commands deliberately stay on the placeholder.

## Install layout

Copy the export root `manifest.json` to `client/NUI/previews/manifest.json`. Copy the contents of the exported `previews/` directory into `client/NUI/previews/`, preserving the relative paths in the manifest. For example, `previews/stem/runId/preview.png` must exist at `client/NUI/previews/stem/runId/preview.png`. The existing `fxmanifest.lua` includes the manifest and `client/NUI/previews/**/*.png`. No media is committed or generated by FiveM.

## Verification

Run `node --test tests/preview-*.test.mjs` from this repository root. These source regressions use mocked image/DOM behavior and do not require Windows or FiveM. Passing them verifies code behavior only; real export installation, APNG playback in FiveM CEF, identity coverage, and server performance still require acceptance testing. The animated media panel is separate from RPEmotes' existing in-game ped preview and placement callbacks.
